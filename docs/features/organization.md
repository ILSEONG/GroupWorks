# 조직도와 연락망

## 구현 목표

ERP 시스템은 개인 업무만 처리하는 시스템이 아닙니다.
조직 안에서 누가 어느 부서에 있고, 어떤 직급인지 확인할 수 있어야 합니다.

특히 다음 기능들은 조직 구조와 밀접하게 연결됩니다.

- 전자결재
- 메일
- 휴가 승인
- 부서별 게시판
- 업무 담당자 확인

그래서 조직도와 연락망 기능을 구현했습니다.

## 조직도 요청 흐름

```text
사용자가 조직도 페이지 접근
→ 전체 부서 목록 조회
→ 선택한 부서 ID 확인
→ 해당 부서의 사원 목록 조회
→ 해당 부서의 직급 목록 조회
→ Model에 데이터 저장
→ 조직도 화면 렌더링
```

조직도에서는 전체 부서 목록을 가져오고, 선택한 부서에 속한 사원 목록과 해당 부서의 직급 목록을 조회해 화면에 전달했습니다.

## 연락망 요청 흐름

```text
사용자가 연락망 페이지 접근
→ 전체 부서 목록 조회
→ 부서명, 위치, 연락처 정보 전달
→ 연락망 화면 렌더링
```

연락망에서는 전체 부서 목록을 조회해 부서명, 위치, 연락처 등을 확인할 수 있도록 구성했습니다.

## 데이터 조회 방식

부서 목록은 DepartmentRepository의 `findAll()`을 통해 조회한 뒤 DTO로 변환했습니다.
사원 목록은 부서 ID를 기준으로 조회한 뒤 DTO 리스트로 변환했습니다.

이렇게 엔티티를 바로 화면으로 전달하지 않고 DTO로 변환하면, 화면에 필요한 데이터만 전달할 수 있고 계층 간 역할도 더 명확해집니다.

## 장점

- ERP 시스템에서 필요한 조직 기반 조회 기능을 구현했습니다.
- 부서와 사원 데이터를 연결해서 화면에 보여주는 흐름을 경험했습니다.
- 메일, 전자결재, 휴가 같은 기능과 연결될 수 있는 기반 기능을 만들었습니다.

## 아쉬운 점과 개선 방향

- 조직도 UI를 더 시각적으로 개선하면 좋습니다.
- 부서 계층 구조가 깊어질 경우 트리 구조로 표현하는 방식도 고려할 수 있습니다.
- 사원 검색, 부서 검색, 직급 필터링이 추가되면 사용성이 더 좋아질 것 같습니다.
