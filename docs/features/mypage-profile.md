# 마이페이지와 내 정보 수정

## 구현 목표

마이페이지에서는 로그인한 사용자가 자신의 정보를 확인하고, 비밀번호, 휴대폰 번호, 주소 같은 개인 정보를 수정할 수 있도록 구현했습니다.

## 마이페이지 요청 흐름

```text
사용자 마이페이지 접근
→ 세션에서 로그인 사용자 정보 조회
→ employeeId로 DB에서 최신 사용자 정보 조회
→ 사수 정보가 있으면 사수 정보 추가 조회
→ Model에 employee, supervisorEmployee 저장
→ Thymeleaf 화면 렌더링
```

세션에 저장된 정보만 사용하지 않고 DB에서 다시 조회한 이유는 최신 정보를 보여주기 위해서입니다.
예를 들어 전화번호나 주소를 변경했다면, 마이페이지에서는 변경된 정보가 바로 보여야 합니다.

## 비밀번호 변경 흐름

```text
비밀번호 변경 요청
→ 세션에서 현재 로그인 사용자 확인
→ DB에서 사용자 정보 조회
→ 사용자가 입력한 현재 비밀번호 검증
→ 일치하면 새 비밀번호 BCrypt 암호화
→ 사용자 정보 저장
→ 성공 응답 반환
```

비밀번호 변경은 민감한 작업이기 때문에 로그인 상태라고 해도 현재 비밀번호를 한 번 더 확인하도록 했습니다.

## 휴대폰 번호 변경과 SMS 인증

휴대폰 번호 변경은 단순히 DB 값을 바꾸는 기능처럼 보이지만, 실제 서비스에서는 사용자가 입력한 번호가 본인의 번호인지 확인해야 합니다.
그래서 휴대폰 번호 변경 전에 인증번호를 문자로 발송하도록 구현했습니다.

SMS 발송에는 CoolSMS API를 사용했습니다.

### SMS 인증 요청 흐름

```text
사용자가 새 휴대폰 번호 입력
→ 클라이언트에서 인증번호 생성
→ /employee/send-one 요청
→ 서버에서 CoolSMS 메시지 객체 생성
→ 발신 번호 복호화
→ 수신 번호로 인증번호 문자 발송
→ 사용자가 인증번호 입력
→ 인증 성공 시 휴대폰 번호 변경 요청
```

## 왜 Jasypt를 사용했는가?

SMS 발송에는 발신 번호나 API 관련 설정값처럼 외부에 노출되면 안 되는 값이 포함됩니다.
이런 값을 설정 파일에 평문으로 저장하면 보안상 좋지 않습니다.

그래서 Jasypt를 사용해 민감한 설정값을 암호화해서 관리했습니다.
컨트롤러에서는 암호화된 발신 번호 값을 주입받고, 실제 SMS 발송 시 복호화해서 사용했습니다.

## 휴대폰 번호 변경 흐름

```text
SMS 인증 완료
→ /employee/modifyphonenumber 요청
→ 세션에서 현재 로그인 사용자 확인
→ 새 휴대폰 번호를 DTO에 반영
→ employeeId 기준으로 DB 업데이트
→ 성공 응답 반환
```

## 주소 변경 흐름

```text
주소 변경 요청
→ 세션에서 현재 로그인 사용자 확인
→ 새 주소를 DTO에 반영
→ employeeId 기준으로 DB 업데이트
→ 성공 응답 반환
```

## 구현하면서 고민한 점

SMS 인증 기능에서 중요한 것은 인증번호를 어디서 생성하고 어디서 검증할 것인가입니다.
현재 구조에서는 클라이언트에서 인증번호를 생성하고 서버가 해당 번호를 문자로 발송하는 방식입니다.
학습용 프로젝트에서는 이해하기 쉬운 구조지만, 실제 운영 환경이라면 서버에서 인증번호를 생성하고 Redis 같은 저장소에 TTL과 함께 저장한 뒤 검증하는 방식이 더 안전합니다.

```text
서버에서 인증번호 생성
→ Redis에 phoneNumber:code 형태로 3분 저장
→ SMS 발송
→ 사용자가 인증번호 입력
→ 서버에서 Redis 값과 비교
→ 일치하면 휴대폰 번호 변경 허용
```

## 장점

- 마이페이지에서 개인 정보를 조회하고 수정하는 흐름을 구현했습니다.
- BCrypt를 사용해 비밀번호 변경 시 보안성을 확보했습니다.
- CoolSMS SDK를 사용해 외부 API 연동 경험을 쌓았습니다.
- Jasypt를 사용해 민감 정보 암호화 관리 경험을 했습니다.

## 아쉬운 점과 개선 방향

- 인증번호를 서버에서 생성하고 TTL과 함께 저장하는 방식으로 개선할 수 있습니다.
- 인증번호 재전송 제한과 요청 횟수 제한을 추가하면 더 안전합니다.
- 실제 운영 환경이라면 API Key, 발신 번호, 암호화 키 관리 방식을 더 엄격하게 설계해야 합니다.
