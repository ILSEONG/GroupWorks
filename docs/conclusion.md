# 마무리 정리

## 전체적으로 배운 점

GroupWorks에서 담당한 기능들은 ERP 시스템의 사용자 기반 기능에 가까웠습니다.

- 로그인으로 사용자 인증을 처리하고
- 마이페이지에서 개인 정보를 확인하고
- SMS 인증으로 휴대폰 번호 변경을 검증하고
- 이메일로 내부 커뮤니케이션을 지원하고
- 화상회의로 실시간 협업을 가능하게 하고
- 조직도와 연락망으로 회사 구조를 확인할 수 있게 했습니다.

기술적으로는 Spring Security, BCrypt, WebSocket, WebRTC, MongoDB, CoolSMS, Jasypt 등을 직접 사용해보면서 각각의 기술이 어떤 문제를 해결하기 위해 필요한지 경험할 수 있었습니다.

## 기술별로 이해한 역할

| 기술 | 사용한 이유 |
| --- | --- |
| Spring Security | 로그인, 인증, 세션, 로그아웃 흐름 관리 |
| BCrypt | 비밀번호 단방향 암호화 저장 |
| MongoDB | 메일 데이터를 문서 단위로 저장 |
| WebRTC | 브라우저 간 실시간 음성/영상 통신 |
| WebSocket | WebRTC signaling 데이터 전달 |
| CoolSMS | 휴대폰 인증번호 문자 발송 |
| Jasypt | 민감한 설정값 암호화 관리 |
| Thymeleaf | 서버 사이드 렌더링 화면 구성 |
| Spring Data JPA | 사원, 부서 등 관계형 데이터 처리 |

## 기억에 남는 부분

가장 기억에 남는 부분은 WebRTC와 WebSocket을 함께 사용한 화상회의 기능입니다.
처음에는 WebRTC만 사용하면 화상회의가 바로 될 것이라고 생각했습니다.
하지만 실제로는 서로의 SDP 정보와 ICE Candidate를 교환하는 signaling 과정이 필요했습니다.
이 과정에서 WebSocket의 역할을 이해할 수 있었습니다.

또 이메일 기능을 구현하면서는 RDB만 사용하는 방식에서 벗어나 MongoDB를 적용해보며, 데이터 구조에 따라 저장소를 다르게 선택할 수 있다는 점을 배웠습니다.

## 다음에 개선해보고 싶은 점

### 인증 / 보안

- CSRF 보호 전략 적용
- 권한별 접근 제어 강화
- 관리자 / 일반 사용자 권한 분리
- 비밀번호 변경 정책 강화

### SMS 인증

- 인증번호 서버 생성 방식으로 변경
- Redis에 인증번호 TTL 저장
- 인증번호 재전송 제한
- 인증 요청 횟수 제한

### 이메일

- 첨부파일 MIME type 검증
- 파일명 중복 방지
- 다운로드 권한 검증
- 대용량 파일 업로드 제한
- MongoDB와 RDB 간 데이터 정합성 관리

### 화상회의

- 방 정보를 Redis에 저장
- 서버 재시작 후에도 방 상태 유지
- TURN 서버 도입 검토
- 다자간 회의를 위한 SFU 구조 학습
- 회의 참여자 목록 관리

### 조직도

- 트리 형태 조직도 UI
- 사원 검색
- 부서 검색
- 직급 필터링

## 결론

이번 프로젝트를 통해 기술은 단순히 유명해서 사용하는 것이 아니라, 해결해야 할 문제에 맞게 선택해야 한다는 점을 배웠습니다.

- 인증과 세션 관리는 Spring Security
- 비밀번호 저장은 BCrypt
- 문서형 메일 데이터는 MongoDB
- 실시간 signaling은 WebSocket
- 브라우저 간 미디어 통신은 WebRTC
- 문자 인증은 CoolSMS
- 민감 정보 관리는 Jasypt

각 기술이 맡는 역할이 명확했고, 직접 구현하면서 그 이유를 이해할 수 있었습니다.
GroupWorks는 단순 CRUD를 넘어 실제 업무 시스템에 필요한 인증, 커뮤니케이션, 실시간 협업, 조직 관리 기능을 경험해볼 수 있었던 프로젝트였습니다.
